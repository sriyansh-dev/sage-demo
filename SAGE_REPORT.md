## Code review

The repository provides a small inventory toolkit and configuration loader, but contains critical bugs and security flaws. The `total_price` function ignores item quantities, leading to incorrect totals, and `average_price` can raise a ZeroDivisionError on empty input. YAML loading uses unsafe `yaml.load` and shell utilities execute commands without sanitization, posing security risks. Tests fail due to these logic errors and unsafe practices. Refactoring and proper error handling are needed to improve correctness, safety, and maintainability.

**Strengths**
- Simple, well‑documented functions with clear intent
- Small codebase makes it easy to audit and extend
- Tests cover basic functionality for shell utilities

| Severity | Location | Issue | Suggestion |
|---|---|---|---|
| high | `inventory.py` | `total_price` adds only `item["price"]` and ignores `item["qty"]`, producing wrong totals; also returns rounded float which may hide precision issues | Multiply price by quantity: `total += item["price"] * item.get("qty", 1)` and consider using Decimal for monetary values |
| high | `inventory.py` | `average_price` divides by `len(items)` without checking for empty list, causing ZeroDivisionError | Return 0.0 when `items` is empty or raise a descriptive exception |
| high | `config.py` | Uses `yaml.load` without specifying a Loader, which can execute arbitrary code when parsing untrusted YAML | Replace with `yaml.safe_load` or explicitly use `yaml.load(f, Loader=yaml.SafeLoader)` |
| high | `shell_utils.py` | Executes shell commands directly (e.g., via `os.system` or `subprocess`) without sanitizing input, opening command injection vulnerabilities | Use `subprocess.run` with `shlex.split` and avoid `shell=True`; validate or escape path arguments |
| medium | `inventory.py` | `apply_discount` calculates discount as `price * percent / 100` which returns the discount amount, not the final price | Return `price - (price * percent / 100)` or rename function to reflect its purpose |
| low | `inventory.py` | Functions return rounded floats which may introduce cumulative rounding errors | Consider returning raw values and let callers format/round as needed |

**Optimization opportunities**
- Use list comprehensions or generator expressions consistently for clarity (e.g., `total = sum(item["price"] * item.get("qty",1) for item in items)`
- Replace manual rounding with `Decimal.quantize` for monetary calculations to avoid floating‑point inaccuracies
- Cache parsed YAML config if loaded repeatedly to reduce I/O overhead

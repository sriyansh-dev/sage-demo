## Code review

The repository provides a small inventory utility and a CLI that reports stock values, but several logic errors and security concerns undermine its reliability. Core functions miscalculate totals and discounts, and lack defensive checks for empty inputs. Unsafe YAML loading and direct shell command execution expose the code to injection attacks. Tests fail because the authentication helpers depend on environment configuration not covered here, and the codebase would benefit from clearer structure and error handling.

**Strengths**
- Simple, well‑named modules make the intent easy to understand
- Functions are short and have low cyclomatic complexity
- Use of type‑agnostic data structures keeps the demo lightweight

| Severity | Location | Issue | Suggestion |
|---|---|---|---|
| high | `inventory.py` | total_price sums only item['price'] and ignores 'qty', producing an incorrect total value | Multiply price by quantity: total += item['price'] * item.get('qty',1) |
| high | `inventory.py` | apply_discount returns price * percent / 100, which yields the discount amount instead of the discounted price | Return the net price: round(price * (1 - percent / 100), 2) |
| high | `inventory.py` | average_price divides by len(items) without guarding against an empty list, raising ZeroDivisionError | Return 0.0 when items is empty or handle the case explicitly |
| high | `config.py` | yaml.load is used without specifying SafeLoader, allowing execution of arbitrary Python objects | Replace with yaml.safe_load or explicitly pass SafeLoader |
| high | `shell_utils.py` | Shell command execution is performed without sanitizing input, creating a command injection vector | Use subprocess.run with a list of arguments and avoid shell=True; validate or whitelist inputs |
| medium | `main.py` | The script relies on the environment variable GROQ_API_KEY but does not provide a fallback or clear error if missing | Add explicit error handling or a user-friendly message when the key is absent |
| low | `inventory.py` | apply_discount and average_price round to two decimals, which may hide precision issues in financial calculations | Consider using Decimal for monetary values if higher accuracy is required |

**Optimization opportunities**
- Combine total_price, apply_discount, and average_price into a single class to reduce repeated iteration over the items list
- Cache the result of yaml.safe_load if the configuration file is read multiple times
- Replace manual string formatting in main.py with f‑strings that limit precision only where needed

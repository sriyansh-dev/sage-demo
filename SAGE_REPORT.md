## Code review

The repository provides a small inventory utility and a CLI that reports stock values, but several core functions contain logical bugs and lack robust error handling. Security concerns arise from unsafe YAML loading and direct shell command execution without sanitization. Tests fail due to incorrect header construction and missing API key handling. Overall code is simple but needs correctness fixes, safer defaults, and better input validation.

**Strengths**
- Clear module separation between inventory logic and CLI entry point
- Comprehensive unit tests covering key functions
- Use of type‑agnostic rounding for monetary values
- Readable docstrings and straightforward naming

| Severity | Location | Issue | Suggestion |
|---|---|---|---|
| high | `inventory.py` | `total_price` adds only `item["price"]` and ignores `qty`, producing an incorrect total for stock values. | Multiply price by quantity: `total += item["price"] * item.get("qty", 1)` and handle missing keys gracefully. |
| high | `inventory.py` | `apply_discount` returns `price * percent / 100` which is the discount amount, not the final price after discount. | Return `round(price * (1 - percent / 100), 2)` and validate that `percent` is between 0 and 100. |
| high | `inventory.py` | `average_price` divides by `len(items)` without checking for an empty list, raising `ZeroDivisionError`. | Return `0.0` when `items` is empty: `if not items: return 0.0` before the division. |
| high | `config.py` | Uses `yaml.load` without specifying a loader, which can execute arbitrary code when parsing untrusted YAML. | Replace with `yaml.safe_load` or explicitly pass `Loader=yaml.SafeLoader`. |
| high | `shell_utils.py` | Executes shell commands directly (e.g., `subprocess.run(cmd, shell=True)`) without input sanitization, opening command injection risks. | Use `subprocess.run` with `shell=False` and pass arguments as a list; validate or whitelist allowed commands. |
| medium | `tests/test_ai_summary.py` | `build_auth_headers` is called without passing the API key, yet the function likely expects a key argument, causing test failure. | Modify `build_auth_headers` to retrieve the key internally (e.g., from env) or accept a parameter; update tests accordingly. |
| medium | `tests/test_ai_summary.py` | `get_groq_api_key` assumes the environment variable is set; if missing, it may return `None` and cause attribute errors. | Add explicit error handling that raises a clear exception when the key is absent, and document the requirement. |

**Optimization opportunities**
- Combine `total_price` and `average_price` calculations in a single pass to reduce iteration overhead for large inventories
- Cache the result of `os.environ.get("GROQ_API_KEY")` in `main` to avoid repeated lookups
- Use f‑strings consistently for string formatting in `inventory.py` for readability
